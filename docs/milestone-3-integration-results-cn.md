## 6.1. 集成概述

第三次更新标志着项目从组件级开发迈向系统级集成。随着 Query Engine、Media Engine、AgentCoordinator、ForumEngine 和 ReportEngine 五大子系统均达到功能成熟状态，工作重心转移至将其串联为一条完整的端到端流水线。

| 子系统 | 流水线角色 | 集成状态 |
|---|---|---|
| **Query Engine** | 基于 Tavily + DeepSeek 的网络证据采集与推理 | 已完成，产出结构化证据 JSON |
| **Media Engine** | 基于 Anspire/Bocha 搜索的多模态跨平台内容分析（抖音、快手、小红书） | 已完成，产出媒体分析报告 |
| **AgentCoordinator** | 多视角审议、CSSD 分歧矩阵、事实-观点分离、CRAG 缺口填补 | 已完成，消费双 Agent 输出并产出协调器综合报告 |
| **ForumEngine** | 多 Agent 讨论论坛，支持 Query Agent、Media Agent 与 Host 之间的结构化辩论 | 已完成，论坛日志实时推送至前端 |
| **ReportEngine** | 模板驱动的报告生成，含交互式图表，支持 HTML/PDF/MD 导出 | 已完成，产出最终交付报告 |
| **Flask 编排器** (`app.py`) | 统一生命周期管理、子进程编排、Socket.IO 日志流、REST API | 已完成，作为系统中枢运行 |

## 6.3. 集成成果

### 6.3.1. 统一前端控制面板

单页 Flask 应用（`templates/index.html`）作为统一操作面板：

- **一键启停**所有子系统
- **实时日志流**通过 Socket.IO 推送所有子进程输出
- **LLM 配置**与 `.env` 双向同步，无需重启即可修改
- **嵌入 Streamlit 视图**展示 Media Agent (:8502) 和 Query Agent (:8503)
- **论坛聊天**实时显示多 Agent 对话
- **报告预览**支持一键下载 HTML/PDF/MD

### 6.3.2. 子进程编排

`app.py` 管理三个子进程和一个后台线程的完整生命周期：

- Media Agent Streamlit 子进程（端口 8502）
- Query Agent Streamlit 子进程（端口 8503）
- ForumEngine 后台线程
- ReportEngine Flask Blueprint

所有进程启动时伴随健康检查轮询、端口冲突解决，关闭时支持优雅终止及强制终止兜底。

### 6.3.3. 配置管理

LLM 配置面板实现了真正的 `.env` 双向同步：

- 通过 `GET /api/config` 读取当前配置
- 通过 `POST /api/config` 写入更新，即时持久化到磁盘
- 系统运行期间配置锁定，防止热重载冲突
- 支持全部七个 LLM 端点（Insight、Media、Query、Report、MindSpider、ForumHost、KeywordOptimizer）及搜索工具配置

## 6.4. 阶段性成果

### 6.4.1. 报告生成

集成流水线已成功产出完整的分析报告。以 2026 年 5 月 24 日生成的报告为例（`output/final_report_DeepSeek_latest_update_20260524_220313.html`，2.3 MB），展示了以下能力：

- **多章节结构**，叙事连贯
- **交互式数据可视化**（Chart.js 渲染图表）
- **带来源引用的证据**，可追溯出处
- **跨源分歧分析**，含 CSSD 指标
- **事实-观点分离**，标注清晰
- **偏见与信息茧房警告**（检测到时触发）

### 6.4.2. 输出格式

三种导出格式均已验证可用：

| 格式 | 状态 | 备注 |
|---|---|---|
| **HTML** | 正常 | 完整交互式报告，含嵌入图表与样式 |
| **PDF** | 正常 | 服务端 WeasyPrint 渲染；完整中日韩字符支持需 Pango 库 |
| **Markdown** | 正常 | 原始源文件，便于存档及二次处理 |

### 6.4.3. 流水线吞吐量

从用户查询到可下载报告的完整流水线在合理时间内完成：

- Agent 并行执行：视搜索深度和内容量而定
- 协调器审议：通常在 3 分钟以内
- 报告生成：逐章生成，每章约 1–2 分钟
- 端到端总计：标准分析约 8–15 分钟

## 6.5. 质量评估

### 6.5.1. 表现良好的方面

- **Agent 互补性**：Query Agent 和 Media Agent 持续产出互补而非冗余的证据 —— Query Agent 在结构化数据和官方来源方面表现突出，Media Agent 则捕获平台特有的情感倾向和多模态内容
- **分歧处理**：CSSD 矩阵成功识别不同平台或查询策略产生冲突情感分布的场景，审议引擎保留这些分歧而非将其折叠为笼统的结论
- **报告连贯性**：即使各章由独立的 LLM 调用生成，最终报告仍能保持章节间的叙事连贯
- **系统鲁棒性**：编排器的健康检查和自动重启逻辑能够优雅处理瞬时故障

### 6.5.2. 可改进的方面

- **报告生成耗时**：逐章生成本质上是串行的，并行章节生成可减少总耗时
- **DeepSeek 模型能力边界**：当前 `deepseek-chat` 模型在复杂审议任务中的推理质量尚可但非最优；升级至更强的模型将改善 CSSD 解读和偏见分析质量
- **报告视觉打磨**：图表样式和排版功能可用，但仍有设计优化的空间

## 6.7. 结论

第三次更新确认了多 Agent 舆情分析系统的所有组件已成功集成为一条可运行的端到端流水线。系统接收用户查询，将分析任务并行派发给 Query Agent 和 Media Agent，通过 AgentCoordinator 审议引擎协调双源输出，经由 ForumEngine 捕获 Agent 间的结构化讨论，最终产出一份结构化、证据可追溯、多格式的最终报告。

临时前端提供了完整的操作控制和实时可观测性。虽然界面视觉打磨和部分性能优化留作后续工作，但核心研究贡献 —— 一个可感知分歧、有偏见意识、多视角的舆情分析系统 —— 已投入运行并产出可展示的成果。
